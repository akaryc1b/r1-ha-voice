# R1 HA Voice

让斐讯 R1 通过 Home Assistant 控制家居、通过 Music Assistant 播放 Apple Music，并使用自己选择的语音识别和 AI 服务。

**R1 负责收音和发声，N1 运行服务。** 日常更换云端语音模型、音色和接口，可以在 R1 的网页中完成。

[安装教程](docs/INSTALL.md) · [配置说明](docs/CONFIGURATION.md) · [备份与恢复](docs/BACKUP_RESTORE.md)

[![CI](https://github.com/akaryc1b/r1-ha-voice/actions/workflows/ci.yml/badge.svg)](https://github.com/akaryc1b/r1-ha-voice/actions/workflows/ci.yml)

## 能做什么

| 功能 | 使用方式 |
| --- | --- |
| 听 Apple Music | 按歌名、歌手或风格点歌，也可以随机听歌 |
| 控制播放 | 暂停、继续、上一首、下一首，调整音乐音量 |
| 控制家居、查询温湿度 | 使用 Home Assistant 已接入的设备和传感器 |
| AI 问答 | 普通问题交给你配置的聊天模型 |
| 多指令与连续对话 | 一句话按顺序做多个操作；可开启回复后的短时免唤醒续听 |
| 更换识别和播报服务 | 网页填写 ASR 模型，选择设备播报或云端 TTS |
| 查看语音处理过程 | 开启日志，查看转写文字、分流和调用结果 |

接入后可以试试：

> “播放周杰伦的晴天” · “播放国语流行” · “随机播放点音乐”
>
> “暂停” · “卧室温度多少” · “彩虹是怎么形成的”

温湿度查询需要先把 HA 中的传感器分配到对应房间。电脑开关机需要额外配置，见 [可选功能](ha/optional/)。

## 需要准备什么

- **斐讯 R1**：已安装兼容的改造语音应用，能通过 ADB 连接。
- **N1**：ARM64 OpenWrt，已有 Docker 和 Python 3；当前方案在约 2 GB 内存的 N1 上部署。
- **Home Assistant 和 Music Assistant**：已有安装可以继续使用。
- **Apple Music 有效订阅**：在 Music Assistant 中完成授权。
- **语音 / AI 接口**：使用云端识别、合成或问答时，准备对应服务的地址、密钥和模型名称。
- R1、N1 和配置用的电脑或手机处于同一局域网。

仓库提供源码、配置模板和安装说明。R1 客户端构建需要你自己的匹配 APK 备份，方法见 [客户端构建与安装](docs/BUILD.md)；模型和运行环境按安装教程另外准备。

### N1 要安装哪些服务？

| 组件 | 作用 | 本仓库验证过的版本 |
| --- | --- | --- |
| Home Assistant | 家居、传感器、点歌规则和面板 | Container 2026.10.1 |
| Music Assistant | Apple Music 授权、音乐库和队列 | 2.10.6 |
| Sherpa-ONNX 与中文模型 | 判断一句话何时说完，可选本地转写 | 1.13.8，Zipformer 14M INT8 |
| 语音网关 | 连接识别接口、处理指令和播报 | 本仓库 `gateway/` |
| Snapcast / R1 Snapdroid | 将 MA 的音乐送到 R1 | Snapserver 0.34.0，Snapdroid 0.29.0.2 |

语音网关和 Snapserver 复用 MA 容器，当前部署保留 HA、MA 两个长期容器。HA Container 中添加 MA 集成后，MA 服务仍需独立运行。

详细依赖、下载来源和启动命令见 [N1 安装教程](docs/INSTALL.md)。

已有 N1 可以沿用当前部署。新部署还可选择 [独立语音容器](deployment/README.md)，将网关和断句服务放在一个容器里；它不代替 HA / MA，也不需要与原语音服务同时运行。

## 安装顺序

1. **准备 N1 环境。** 保留已有 HA / MA，安装本地断句服务和语音网关。
2. **连接音乐来源和音箱。** 在 MA 授权 Apple Music，连接 R1 Snapdroid，将 Snapcast 选为 R1 的首选输出。
3. **接入 HA。** 导入音乐规则和面板，填写自己的播放器、房间和传感器。
4. **配置 R1。** 在 8080 填写网关和语音参数；在 HA、AI 设置页完成各自连接。
5. **逐项试用。** 先在 MA 播放音乐，再测试语音暂停、点歌、温湿度和问答。

第一次安装请从 [完整教程](docs/INSTALL.md) 开始。教程中的 IP、播放器 ID、容器名和实体都是部署示例，需要替换成自己的值。

HA 的地址、队列和音乐来源集中写在一份设置中，再生成部署文件。播放卡片支持 [HACS 自定义仓库安装](docs/HACS.md)；安装卡片后，仍需导入音乐脚本和面板。

## 日常配置

### 更换识别模型

打开 R1 控制页 → **语音识别与播报**：

1. 选择包含“可配置云端 ASR”的识别模式。
2. 填写 ASR 模型 ID、API 基础地址和密钥。
3. 按需设置备用模型、超时和“明确短指令优先本地识别”。
4. 点击 **保存语音设置**，下一轮识别生效。
5. 点击 **测试已保存的 ASR** 检查接口；该按钮只转写合成录音，不执行指令。

示例使用 `TeleAI/TeleSpeechASR`，备用 `FunAudioLLM/SenseVoiceSmall`，默认关闭本地文字优先。云端识别仍使用本地服务判断句尾。完全离线识别可另选，但小模型对歌名和开放式问题的识别能力有限。

服务必须支持音频转写；聊天模型不能直接作为 ASR。换本地模型需要另行部署文件，详见 [配置说明](docs/CONFIGURATION.md)。

### 更换音色和调整音量

在同一页面的 **回答播报** 中：

- **设备自带音色**：使用设备的文字播报能力。
- **云端 TTS**：填写接口和模型，通过下拉框选择音色。CosyVoice2 提供八种预置音色，也可填写 **自定义音色 ID**。
- 音乐音量和助手播报音量可以分别调整。

点击 **保存语音设置** 后，下次播报生效。设备自带音色只负责播报，不会重新启用旧助手的问答通道。

### 开启诊断日志

打开 **日志** 页，勾选 **保存诊断日志**，选择等级，再点击 **保存日志设置**。

保存一次后自动记录，不需要一直打开网页。排查问题可选 `DEBUG`；`WARN` / `ERROR` 只保留达到相应等级的事件，正常操作可能没有记录。

日志只保存开启后的事件，不保存录音和密钥。关闭后保留历史，点击 **清空诊断日志** 才删除已有记录。详情见 [日志说明](docs/voice-logs.md)。

## 语音会交给谁处理？

- **暂停、继续、切歌等明确控制**：可以直连 MA，或在网页选择经 HA 执行。
- **歌名、歌手、风格点歌**：HA 搜索并交给 MA 播放。
- **家居和温湿度**：HA。
- **普通问题**：AI 设置页配置的聊天模型。

“播放”通常继续当前队列；“随机播放点音乐”“来点音乐”选择随机歌单。“国语精选”目前作为国语流行风格搜索，不保证命中自己创建的同名歌单。

使用直连 MA 时，可在“音乐播放与音源”修改随机听歌的默认搜索词和音乐来源；留空来源表示不限来源，点击“保存音乐设置”生效。

## 常见问题

**MA 装进 HA 就不用再运行服务了吗？**

HA 中的 MA 集成负责连接 MA。当前使用 HA Container，MA 服务仍在自己的容器运行。

**换模型为什么没有生效？**

确认点了对应页面的保存按钮，再刷新回读。ASR、TTS 和聊天 AI 是不同配置，模型需要与接口支持的用途一致。

**放歌时听不清，怎么办？**

确认已开启“收音时临时静音音乐”。开启 DEBUG 日志后重试，先看转写是否正确，再看指令交给了谁。空或不完整转写可在提示结束后自动重说一次；所有识别服务均故障时提示服务未响应。

**为什么切歌后还要等？**

Apple Music 取流、服务端准备和 R1 缓冲都会影响等待。后台准备完成不代表已经听见新歌，当前没有承诺固定的首播或切歌秒数。详情见 [性能记录](docs/PERFORMANCE.md)。

**FLAC 传输就是 Apple Music 无损吗？**

当前已验证的 Apple 音源是 AAC，局域网使用 FLAC 避免再次有损编码。原始音源和 R1 硬件链路仍决定最终音质。

**备份仓库就能恢复所有配置吗？**

还需要另存 HA / MA 数据、个人令牌、音源授权和 R1 APK。公开仓库不包含这些私人内容，按 [备份与恢复](docs/BACKUP_RESTORE.md) 操作。
