# R1 语音助手：环境与配置备份

这份仓库重点记录 **N1 要安装什么、R1 如何连接、HA/MA 如何配置**，并保存当前网页和语音网关源码。镜像、模型、运行库、APK 和账号授权不打包进 Git。

**8080 现在可以填写具体 ASR 模型、API 地址、密钥、超时和备用模型。保存后下一轮生效，换云端模型无需重新改代码或刷机。**

## N1 要装什么

| 项目 | 当前已验证环境 | 用途 |
| --- | --- | --- |
| 系统 | ARM64 OpenWrt，N1 约 2 GB 内存 | 宿主环境 |
| Docker | 保留现有 Docker 和容器 | 运行 HA / MA |
| Python 3 | OpenWrt 宿主 Python 3 | 启动本地识别、管理服务 |
| Home Assistant | Container **2026.10.1**，8123 | 家居控制、点歌规则和面板 |
| Music Assistant | **2.10.6**，8095，host 网络 | Apple Music、队列和 Snapcast / AirPlay 播放 |
| 本地语音识别 | Sherpa-ONNX **1.13.8** ARM64 | 短指令识别和句尾断句 |
| 本地模型 | 中文 Zipformer **14M INT8** | encoder / decoder / joiner / tokens |
| glibc 兼容库 | 当前 Debian ARM64 **glibc 2.41** + libgcc / libstdc++ | 在 OpenWrt musl 上运行上述识别程序 |
| 网关 Python 依赖 | **aiohttp、numpy**，复用 MA 环境 | 音频转写、云端复核、快捷音乐控制 |
| Snapcast 依赖 | snapserver 0.34.0 + provider 的纯 Python 依赖 | R1 Snapdroid 接收音乐，详见 ma/snapcast |
| AirPlay 依赖 | 官方 MA 自带；精简镜像需核对 | 保留 R1 MediaCenter 作为回退 |

**已有 N1 环境不用重装。** 当前长期容器只有 hass 和 r1-apple-music；本地识别由 OpenWrt 服务启动，语音网关复用 MA 的 Python 环境，不另建语音容器。

HA Container 没有 HA OS 的附加组件管理器。HA 中的 MA 集成用于对接，MA 服务仍需运行；不要为了安装“插件”删除原来的 HA。

详细依赖、下载地址、目录和启动命令见 **[N1 环境与启动配置](docs/INSTALL.md)**。

## 使用入口

以下是当前安装示例，迁移时换成自己的 IP：

- R1 配置：http://192.168.1.3:8080/
- HA：http://192.168.1.88:8123/
- MA：http://192.168.1.88:8095/
- HA 音乐面板：http://192.168.1.88:8123/r1-music/music
- N1 语音网关：16068；本地 ASR WebSocket：16066。

## 8080 怎样配置语音

在“语音识别与播报”里：

1. 选择“本地快速控制 + 可配置云端 ASR”。
2. 填写模型 ID，当前使用 FunAudioLLM/SenseVoiceSmall，主模型超时 4 秒；备用 TeleAI/TeleSpeechASR，超时 4 秒。默认关闭本地识别优先。
3. 填写 API 基础地址，例如 https://api.siliconflow.cn/v1，以及密钥。
4. 按需展开超时、备用模型和本地优先设置，保存。
5. 点击“测试已保存的 ASR”，只转写合成“暂停”录音，不执行暂停。

可以手填其他模型，也能读取服务商列表；模型必须支持 WAV 音频的 /audio/transcriptions，聊天/图像模型不能直接当 ASR。

密钥只保存在 N1，页面不回显；留空保留，勾选“清除”才删除。ASR/TTS 模型、接口、密钥分别配置。唤醒词、HA、AI 的原有入口保留，旧云知声识别/问答回退已关闭。

未听清后自动续听一次的开关、AI 流式开关、首正文/首答/整答预算、播报音量兼容通道也在 8080 配置；聊天模型和密钥仍在原 /5 页面。字段及兼容协议见 [配置说明](docs/CONFIGURATION.md)。

## 当前分流

- 转写默认全部走云端；本地模型只负责分段。可在 8080 手动开启明确短指令本地优先。
- 开启本地优先后，含糊、不完整或需纠错的文字仍交云端复核；云端空文字或不完整时提示后续听一次，网络故障退出，不采用猜测执行。
- 播放、暂停、上下首：可直连 MA；歌名/歌手/风格点歌复用 HA。
- 家居与温湿度：HA；普通问题：AI 配置页的大模型。
- 音乐：MA → Snapcast → R1；AirPlay/RAOP 保留回退。播报：设备文字播报或可配置云 TTS。

“播放”恢复原队列；“随机播放点音乐”“来点音乐”“放点歌听”选择随机歌单，暂停/停止可以打断尚未完成的点歌准备。歌名/风格与解释句保持区分，句式从 HA 文件生成，详见 [音乐语义](ha/README.md)。“国语精选”目前按国语流行风格/歌单搜索，不保证匹配个人同名歌单。

## 源码和配置

| 路径 | 内容 |
| --- | --- |
| gateway/ | 网关、统一配置模块、无密钥示例、合成测试音频 |
| device/ | R1 Java 与网页源码、构建报告；不含 APK/厂商 SDK/工具二进制 |
| services/、asr/ | 服务模板、启动器、模型下载地址与 SHA256 |
| ma/ | 同版本源码优化与检查工具；不含镜像和运行库 |
| ha/ | 音乐配置、中文语法、面板；电脑控制单独放在 optional/ |
| tests/ | 隔离 HTTP/WebSocket 测试，使用虚构密钥，不控制真实电脑 |

HA/MA 地址、队列和提供商 ID 来自当前部署，首次安装要改成实际值。默认队列 upbac50e55、Apple Music 实例 apple_music--tP6RUHDy 不是通用 ID。HA 令牌和 MA 令牌不能互换。

## 验证与速度

可配置语音的 16 项网关测试和 12 项音乐抢占测试、网页保存/刷新/热更新、真实 TeleAI/SenseVoice 合成转写、R1 识别专用测试已通过。没有执行电脑电源操作。[验证范围](docs/TESTING.md)

MA 两次切歌的源缓冲准备从 4.014 / 2.892 秒降到 0.438 / 0.452 秒；按钮等待从 1 秒缩到 0.15 秒。两首样本的解码 PCM 校验一致，音质规格保持不变。

当前 Apple 源是 AAC，局域网 FLAC 用于避免再次有损编码；不能把 FLAC 传输等同于 Apple Music 无损音源。R1 的硬件混音链路也可能重采样。

本轮还修复单曲循环下手动下一首未预取的问题：预取完成后的后台加载 6.538 → 0.520 秒，详情见 [当前速度复测](docs/PERFORMANCE.md)。

**源准备时间不等于听见新歌的完整耗时**，Apple 首次取流等待和播放器接收队列仍需分别测量，现场完整听感计时尚未确认。

接收端现场噼啪/发颤已定位到频繁硬同步，硬件 burst 修复与官方 OpenSL 后端的最新对照记录在 [性能说明](docs/PERFORMANCE.md)。仅有连接稳定和系统欠载为零，不能证明听感稳定。

## 恢复与边界

- [备份与回退](docs/BACKUP_RESTORE.md)：账号、令牌、MA/HA 数据必须另存本地；公开仓库不代替个人配置备份。
- [构建说明](docs/BUILD.md)：使用自己匹配的备份 APK 和 Android 构建依赖重建客户端。
- [架构](docs/ARCHITECTURE.md)：R1 / N1 / HA / MA 各自负责什么。
- 云端模型可在网页更换；更换本地 ONNX 模型或断句参数，需要部署模型并重启本地 ASR 服务。
- MA 优化匹配 **2.10.6 的已验证源码哈希**；升级 MA 后先核对，不能强行覆盖旧源码。
- 8080/网关按可信局域网使用，不直接映射到公网。
