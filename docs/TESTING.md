# 验证记录与范围

记录日期：2026-10-13。以下明确区分配置测试、合成语音测试和实际设备音频输出，不能把接口成功等同于现场听感验收。

## 本轮可配置语音

`tests/test_gateway_configuration.py` 的 10 项隔离测试已通过。使用临时目录、模拟 HTTP/WebSocket 服务和虚构密钥，不控制真实电脑：

1. 密钥不回显，留空保留，显式清除与持久化重载。
2. 任意合法模型 ID 与新连接使用热更新后的模型。
3. 明确本地短指令跳过云调用。
4. 含糊本地结果的云端失败返回重说。
5. 显式备用模型生效。
6. 云端空结果和不完整结果不能变成可执行文字。
7. 无效配置不会覆盖已保存配置。
8. 非同源页面不能直接写配置。
9. TTS 使用独立模型、音色和密钥。
10. 模型列表与 MA 地址、队列、令牌可配置。

运行方式（已有 Python 环境中安装 aiohttp、numpy）：

```sh
python -m unittest discover -s tests -v
```

另有 6 项手动下一首预取测试：单曲循环使用手动后继、仅加载详情、旧当前曲/无后继/不可播放项不预取、可选预取失败不打断当前曲、停止取消可以传播。连同上述配置测试，共 16 项在 MA Python 3.14.7 环境通过。

## 真实网页与 R1 验证

- Edge/Playwright 检查桌面与 390px 手机布局，无页面 JavaScript 异常。
- 在 8080 切换 SenseVoice、保存、刷新，模型回读正确，health 立即显示新值。
- 自定义 `custom/asr-model-v99` 可保存、刷新、热更新；没有向服务商调用这个虚构模型。
- 中文 JSON 请求经过 R1 旧网页服务器正常保存，不因 UTF-8 字节长度挂起。
- SenseVoice 和星辰的真实接口合成“暂停”转写成功；测试没有执行暂停动作。
- ASR/TTS/MA 密钥输入框均为空，显示已配置，保存过程保留原值。
- R1 识别专用 `verify` 模式：合成“暂停”和合成问答文字识别通过，无指令分发、无电脑电源操作。
- APK 经 SHA256 与 Android ART 校验，使用覆盖安装，设备网页正常。

最后版本还检查了整轮超时不足时拒绝保存，设备及网关配置保持不变，见 docs/verification/final-browser-guard.json。

JSON 记录见 `docs/verification/browser.json`、`device.json`。接口测试的约 0.15 / 0.74 秒只反映该合成录音的云接口调用，不是用户说完后的完整响应时间。

## 音乐优化验证

上一轮已部署的 MA 源码优化本轮保留：

- 同歌首段 PCM 对照约 3.613 → 0.353 秒；第二首约 2.630 → 0.326 秒。
- 两次实际 MA 切歌的源缓冲 4.014 / 2.892 → 0.438 / 0.452 秒。
- MA 上下首按钮合并连点等待 1 → 0.15 秒。
- 两首歌分别比较前 3 秒和 30 秒，PCM SHA256 完全一致。
- 实际跳转到 90 秒仍使用正常 HTTP Range；暂停/恢复与约 64 秒连续音频帧推进正常，无相关欠载/断流记录。
- 缓存歌曲的一次直接切换命令完成约 2.328 秒；不代表人耳听到新歌的准确时刻。

数据见 `docs/verification/music-skip.json`。RAOP 暖切换可保持同一个 AudioTrack 连续输出，仅凭帧计数不能确认新曲开始，因此本轮完整切歌听感时间仍未确认。

本轮新增单曲循环下手动后继的资料预取，实际加载对照与连续播放验证见 [PERFORMANCE.md](PERFORMANCE.md)。
