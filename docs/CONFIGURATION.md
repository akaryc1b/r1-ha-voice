# 配置说明

## 配置保存在哪里

| 位置 | 保存内容 | 生效方式 |
| --- | --- | --- |
| R1 `/sdcard/r1-local-asr.json` | 网关地址、离线 WS 地址、识别模式、整轮超时、播报引擎、音乐通道 | 下一轮识别/播报 |
| N1 MA 数据下 `r1-cloud-voice/gateway.private.json` | ASR/TTS 接口、密钥、模型、预算、MA 连接 | 大多数设置保存后热更新 |
| 原 R1 `/4` | HA 地址、HA 长期访问令牌 | 按原页面保存 |
| 原 R1 `/5` | 聊天 AI 的接口、密钥、模型与开关 | 按原页面保存 |
| HA 配置 | 点歌规则、实体/区域、MA 令牌、面板、可选电脑控制 | HA 重载/必要时重启 |
| MA 配置 | Apple Music 账户授权、音乐库、播放器协议、队列 | MA 原生设置 |

网页不会把 ASR/TTS 供应商密钥写入 R1 JSON，也不在 URL 中发送密钥。配置读取只返回 `*_configured` 状态。空密钥表示保留，勾选“清除”才删除；新配置校验失败不会覆盖上一份文件。

## ASR

“语音识别模式”有两种：

- **本地快速控制 + 可配置云端 ASR**：音频先经过本地服务断句和识别，默认仅用本地服务断句，全部最终转写交给所选云模型。手动开启“明确短指令优先本地识别”后，完整、明确且足够短的控制句才可采用本地文字。
- **本地离线识别**：R1 直接连接本地识别服务，不调用云端 ASR。开放式问答/歌名的识别能力仍受本地小模型限制。

| 字段 | 默认值 | 含义 |
| --- | --- | --- |
| `asr_base_url` | `https://api.siliconflow.cn/v1` | 服务基础地址；自动追加 `/audio/transcriptions` |
| `asr_model` | `TeleAI/TeleSpeechASR` | 可直接填写的模型 ID，不限于预设列表 |
| `asr_api_key` | 无公开默认密钥 | ASR 接口 Bearer 密钥；本地免鉴权接口可留空 |
| `asr_timeout_seconds` | 4 秒 | 主模型一次调用总超时，范围 1～30 秒 |
| `asr_fallback_model` | `FunAudioLLM/SenseVoiceSmall` | 可选备用模型；空值关闭 |
| `asr_fallback_timeout_seconds` | 2 秒 | 备用模型预算，范围 1～20 秒 |
| `local_first` | false | 完整明确短指令是否优先本地处理 |
| `local_max_chars` | 12 | 本地快捷指令的最大字数；并不取消完整性/纠错检查 |
| `local_asr_url` | `http://127.0.0.1:16066` | 网关访问本地识别的地址 |
| `max_record_seconds` | 18 秒 | 网关允许的最长收音时长，范围 3～30 秒 |

模型 ID 支持字母、数字与 `_ . : / -`，最多 160 字符。这个检查仅判断配置格式，不保证服务商提供该模型。

接口协议为 multipart POST，字段 `model` 和 `file`，文件是 16 kHz、单声道、16 bit PCM WAV；成功响应需含非空 `{"text":"识别文字"}`。只提供聊天/多模态 `/chat/completions` 的服务不能直接填到此处。

当前使用 TeleSpeech 4 秒 + SenseVoice 2 秒备用，并关闭本地文字优先；本地服务仍承担分段，不把其文字用于执行。此前SenseVoice识别成功后，后续四轮均出现4秒超时，故按最新设备日志调整主备与备用预算；这不构成所有远场语音准确率的保证，模型始终可在8080修改。相同合成问题录音中，GSR 多次直接生成答案而非逐字转写，额外提示词也未纠正，因此不再默认用于纯 ASR。模型仍可手填，服务能力需自行验证；备用调用会增加失败时的总等待。

**整轮识别超时**在 R1 侧设置，默认 45 秒，范围 20～120 秒。网页会检查它是否大于“最长收音 + 主模型预算 + 已启用备用预算 + 3 秒”，避免音箱提前关闭还在工作的识别连接。

开启本地优先时，需要同音修正、含糊或不完整的短句仍须云端复核。空结果或不完整结果不执行控制；播放器中的单独“播放”是完整的恢复播放操作。

R1 侧 `asr_retry_once` 默认 true，8080 可关闭：云端只返回空文字或不完整文字时，在错误提示真正播完后续听一次，无需再次唤醒。每原轮最多一次，提示等待上限 12 秒、续听会话上限 15 秒；新唤醒、其他播报或取消废弃旧续听。只要一个候选服务正常返回空文字，就允许这一次重说，即使另一个服务故障；所有候选服务均故障或配置错误时不自动续听。不能按固定延迟猜测提示已经结束。

## 句尾断句和本地声学模型

8080 的“麦克风声道”可设置输入格式 `channels`（1 或 2）和双声道取音方式 `asr_channel_mix`（`left`、`right`、`mix`）。旧配置未指定取音方式时保持左声道；`mix` 按有符号 16 bit 样本求左右平均，用 32 bit 中间值避免相加溢出。单声道不做混音。两个声道都为麦克风时可听测平均效果；若其中一路为回声参考或反相输入，平均可能降低音量，应选主麦声道。不要仅为尝试混音而修改不匹配固件的输入格式。

配置缓存刷新失败会保留上一次合法快照，并按原间隔重试。首次读取尚无合法快照时仍报错，异常保留原始原因；网页写入只有原子提交成功后才更新内存配置。

当前句尾静音是本地 Sherpa 服务的 `--rule2-min-trailing-silence=1.3` 秒，允许句中短暂停顿。此参数不是云端 API 等待时间。

更换离线模型需准备其 ONNX 文件、tokens、相应 `--model-type` 和启动参数；更改断句需编辑 `/etc/init.d/r1-local-asr` 后重启该服务。8080 的模型输入框只选择云端转写模型，不会自动下载本地大模型。实际断句参数请以服务启动参数为准。

## TTS 和音量

“设备自带音色”只读出已有文字，旧识别和问答仍关闭。这不等于保证底层 TTS 完全离线。

云 TTS 可配置以下字段：

| 字段 | 默认值 |
| --- | --- |
| `tts_base_url` | `https://api.siliconflow.cn/v1` |
| `tts_model` | `FunAudioLLM/CosyVoice2-0.5B` |
| `tts_voice` | `FunAudioLLM/CosyVoice2-0.5B:anna` |
| `tts_api_key` | 不公开，独立于 ASR 保存 |
| `tts_timeout_seconds` | 15 秒 |
| `tts_first_chunk_timeout_seconds` | 4 秒 |
| `tts_speed` | 1.0 |
| `tts_gain` | 2.0 |

请求发往 `/audio/speech`，JSON 包含 `model`、`voice`、`input`、`response_format=mp3`、`stream=true`、`speed`、`gain`。服务必须兼容这些字段并返回 MP3；不同供应商的音色名称和扩展参数不一定通用。这个选项不代表已实现 Edge 或所有 TTS 私有协议适配。

TTS 与 ASR 可以使用不同接口和密钥。密钥不会随页面刷新回显；更换配置会清除旧合成缓存。

网关 `/health` 的 `cache_entries` 和 `cache_bytes` 分别显示 TTS 缓存条数与音频字节数；字节数不包含 Python 对象开销。缓存仍采用 LRU，默认最多 32 条、合计 4 MiB。

**音乐音量与助手播报音量分开配置**。部分固件 stream 9 与音乐联动，可在 8080 选择兼容通道 stream 2；当前设备真实回读音乐 4/15、播报 8/15，修改播报后音乐不变。其他设备需回读及听测验证。Snapcast 的高级 r1_hardware_volume_url 可接到 R1 /voice_volume，软件增益保持 unity，直接控制设备音乐音量，避免两层衰减；只对显式配置的播放器生效。

## 音乐、HA 与 AI 分流

- “播放控制直连 MA”：明确的第一首、上下首、暂停、恢复、停止由网关调用 MA；确认播报可以开关。
- “所有音乐指令交给 HA → MA”：使用原有 HA 音乐规则。
- 具体歌名、歌手和风格点歌复用 HA 的搜索脚本，不把“暂停”交给大模型解释。
- 温湿度、电脑控制等明确意图交给 HA。
- 普通问题交给原 AI 配置页的大模型。

“国语精选”目前作为国语流行风格/歌单搜索词，不保证精确匹配用户自己创建的同名歌单。

MA 直连连接字段是 `ma_url`、`ma_queue_id`、`ma_token`。令牌支持原始 token 或带 `Bearer ` 前缀的值。HA 的脚本使用自己的授权文件和队列/提供商 ID，修改网关队列不会自动改写 HA 自动化。

唤醒词、HA 和 AI 的原有配置入口保留。不会为了升级把用户已保存的唤醒词改回“小讯小讯”。

## 网关部署字段

`allowed_clients` 是允许访问网关的客户端 IP 列表，需要保留 `127.0.0.1`，R1 和 N1 地址也必须在内。`r1_control_url` 用于将音乐执行失败反馈给音箱。

`bind_host` / `bind_port` 是网关监听地址，手工修改后需要重启 `/etc/init.d/r1-cloud-voice`；读取接口的 `restart_required` 会提示。它们属于部署配置，不会因为改 ASR 模型而重启服务。

修改 N1 IP 时，同时更新网关监听与允许地址、8080 的网关/离线识别地址、HA 文件中的地址。已有容器、账号、音乐库不需要重建。

## AI 首句播报与等待上限

8080 可配置 ai_streaming（默认 true）、ai_first_content_timeout_ms（4500）、
ai_first_reply_timeout_ms（8000）、ai_answer_timeout_ms（30000）。
界面以秒显示，要求首正文 ≤ 首答 ≤ 整答；不合法配置原子拒绝。
首答预算包括至多一次受控非流式重试；持续返回思考文字不算正文。
首个完整句可播报后即排队，其余句按顺序继续；新唤醒取消旧请求，
过期结果不会再次朗读。关闭流式时也受首答预算约束。

当前 /5 选 Qwen/Qwen3.5-35B-A3B，模型可随时更换。
流式减少等整篇答案的等待，不能保证供应商首段生成速度。
失败会明确提示；不会重新进入旧云知声闲聊通道。

## 收音音乐静音与日志

R1的 `listen_music_mute` 默认true，8080可关闭。仅真实voice会话以API22的同一AudioManager/Binder申请临时Music3静音，启动失败、换轮、看门狗和finally均成对释放；不写音乐volume索引，不静音speech2。不是把音量记为旧值后强制覆盖回去。

日志设置独立保存在N1 `r1-cloud-voice/diagnostic-logs` 中，由8080“日志”控制。默认disabled/INFO，开启后才保存；读等级不改写未保存表单，关闭不删除历史，清空使用generation防止旧批次复活。详细字段和测试见[日志说明](voice-logs.md)。

### 云端播报音色选择

8080 → 语音识别与播报 → 回答播报选择“云端 TTS”后，“播报音色”使用下拉框。CosyVoice2 提供八种带中文名称的预置音色；列表来源于 [硅基流动官方语音合成文档](https://docs.siliconflow.cn/docs/userguide/capabilities/text-to-speech)，实际支持以所用接口为准。选择“自定义音色 ID”可填写克隆音色或其他模型的音色。读取配置、切换模型不会自动覆盖已保存的音色 ID；选好后点击“保存语音设置”，下一次播报生效。

## 随机听歌默认值

网关的 default_random_query 默认为“国语流行”，default_random_providers 默认为 [apple_music]。8080“音乐播放与音源”可修改并保存，来源字段用英文逗号分隔；留空表示不限音乐来源。仅用于直连 MA 的泛泛随机请求，具体歌名/风格仍由 HA 搜索规则处理，不等同于个人收藏推荐。

## 部署参数与共享规则

HA 的 queue_id、provider、r1_url、ma_url 使用 ha/r1_settings.yaml 统一输入，再由 render_config.py 生成部署文件。MA 优化从进程环境 R1_MA_QUEUE_ID 读取目标队列，须与该设置及网关队列一致；环境变更需重启MA，不由网页隐式改容器环境。

MA 环境变量 `R1_APPLE_SEQUENTIAL_SEEK_MAX_SECONDS` 控制 Apple 加密 MP4 顺序读取的续播上限，整数 0～600 秒，默认 120 秒。范围内从头读取、解码后准确截取；更远跳转沿用原 HTTP Range，避免读取过长前缀。设为 0 只优化从头起播，修改后重启 MA。它不改变音频编码、采样率或 Snapcast 缓冲，也不由 8080 语音模型设置修改。

`R1_APPLE_HTTP_PIPE` 默认 `1`：上述范围内、未指定自定义 FFmpeg 网络输入参数时，由 MA HTTP 客户端读取原始加密音频，再送 FFmpeg 解码。它能改善 DNS 返回多个不可达 CDN 地址时的连接等待，不保证网络或 Apple 授权服务始终快速。设为 `0` 恢复 FFmpeg 直接联网，须重启 MA；不修改音源、音质或音箱缓冲。

`R1_APPLE_PLAYLIST_RATINGS_TIMEOUT` 默认 `2` 秒，范围 0～10（支持小数）：Apple 歌单已取得曲目后的可选收藏查询预算。0 跳过该展示查询；超时使用已读取曲目继续准备，不绕过 Apple 必要请求的限流。此设置属于 MA 进程环境变量，修改后重启 MA；不影响收藏同步与写入。详见 [MA 优化说明](../ma/README.md)。

`R1_IDLE_DETAILS_REFRESH` 默认 `1`：待机时在当前歌曲播放详情过期前 30 秒刷新；Apple 默认有效期 600 秒，正常情况下约每 9.5 分钟请求一次资料，不播放音频。每次重新检查队列、曲目和会话，播放中不继续周期刷新。设为 `0` 关闭周期刷新，保留启动预取。修改后重启 MA；不能保证外网持续故障时仍能立即播放。

分类、请求前后缀、同音修正和中文音量数字规则只维护 gateway/intent-rules.json，由生成器编入Java，Python读取同一份JSON。改规则需重启网关并重建客户端；日常改ASR/TTS模型仍只需网页保存。中文数字只在完整音量请求中转成0到100的数字，歌名和普通问答不做数字替换；HA也拒绝无法识别或越界的值，不再静默转为0。

新客户端访问网关/asr时显式使用audio_format=pcm_s16le，16kHz单声道PCM16小端；网关仍接受旧客户端默认Float32。离线直连Sherpa继续使用Float32。不要在PCM16客户端连接旧网关前先单独升级客户端。
